# Безопасность и 152-ФЗ

## Секреты

* Токены hh.ru, текст резюме и контакты шифруются AES-256-GCM (`core/crypto.py`). Associated data
  привязывает шифртекст к пользователю: токен одного пользователя нельзя подставить другому.
* Ключи в `ENCRYPTION_KEYS`; первый шифрует, все расшифровывают — это позволяет ротацию.
* `.env.example` содержит только имена переменных.
* Логи в JSON; ключи вида token/secret/password/email/phone и значения, похожие на email, телефон,
  Bearer-токен, `code=` и `access_token=`, заменяются на `***` (`core/logging.py`).

## Аутентификация

* Пароли: argon2. Сессии на сервере (в cookie только случайный токен, в БД — его хэш), `HttpOnly`, `SameSite=Lax`.
* CSRF: double-submit (`ashore_csrf` + заголовок `x-csrf-token`) на всех изменяющих запросах.
* Ограничение частоты: регистрация, вход (по IP и email), общий лимит API.
* Чужие объекты отвечают 404 (`get_owned`), чтобы не раскрывать существование id.
* OAuth hh.ru: `state` одноразовый, живёт 10 минут и привязан к пользователю, который начал вход.

## Недоверенный ввод

* Текст вакансий — данные, а не инструкции. В AI он передаётся в теге `<untrusted>`, вложенные
  теги вырезаются, системный промпт запрещает выполнять инструкции из него.
* AI не может менять настройки, лимиты или режим: его ответ только корректирует оценку в пределах
  ±10 и добавляет риски. Письмо от AI проходит ту же проверку фактов, что и шаблонное, и при ошибке
  заменяется шаблонным.
* Импортированные пользователем вакансии приватны и не перезаписывают общие записи из API.
* Загрузка файлов: проверка сигнатуры, лимит размера, лимит страниц и защита от zip-бомб.

## Ограничения платформы

* Нет обхода капчи, лимитов и авторизации, нет имитации официальных клиентов hh.ru.
* Капча и `limit_exceeded` останавливают автоматизацию и просят пользователя действовать на сайте.
* Платные услуги hh.ru не покупаются из приложения.

## 152-ФЗ

| Требование | Реализация |
| --- | --- |
| Согласие на обработку | Обязательный флажок при регистрации, время согласия хранится |
| Отдельное согласие на передачу третьим лицам | Внешний AI работает только после отдельного согласия, отзывается в настройках |
| Право на доступ | «Выгрузить данные» — JSON со всеми данными, включая расшифрованное резюме |
| Право на удаление | «Удалить аккаунт» с подтверждением паролем, каскадное удаление всех записей |
| Минимизация | В Telegram уходят только тексты уведомлений, без резюме и токенов |
| Журнал | `audit_logs`: действия пользователя, системы и AI, детали проходят через редактирование |

Перед публичным запуском оператору нужно заполнить реквизиты в `/privacy`, уведомить Роскомнадзор
об обработке ПДн и разместить сервер с базой на территории РФ (требование локализации).
